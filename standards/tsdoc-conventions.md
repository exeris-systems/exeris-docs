# TSDoc Conventions

Binding per ADR-085 §F (amendment 2026-09-06). The TypeScript sibling of `javadoc-conventions.md`: the same twelve rule numbers and the same intent, adapted per rule rather than transliterated. The numbering is a lookup, not a promise of equivalence — rule 4 here (release tags) has no Javadoc analogue, rule 5 folds Javadoc's 4 and 5 together, and Javadoc's rule 6 contract tags (`@implSpec`/`@apiNote`/`@implNote`) have no numbered counterpart, only `@remarks` in the prose below. Applies to every `.ts` source in the ecosystem; the hard gates apply to the **published surfaces**: `@exeris/ai-bridge` (its tool surface), `@exeris-systems/ui-kit` (its exports), `@exeris/codegen-ts` (its config schema and emitted output). Angular applications (`exeris-studio-frontend`, budgetHQ, the landing) are checked on changed files only.

Doc comments are TSDoc (`/** … */`, Markdown inside, tags from the TSDoc core/extended set plus typedoc's organisational tags). They are not Javadoc: no `<p>`, no `{@code}`, no `@author`, types never repeated in tags. TypeScript already carries the types; the comment carries the contract.

## Hard rules

1. **Every exported type, function, class, interface member, enum and constant on a gated package has a doc comment.** `[L1: typedoc --validation.notDocumented --treatValidationWarningsAsErrors on the published entry points; eslint jsdoc/require-jsdoc error on the gated globs, warning elsewhere]`
2. **First sentence is a summary that stands alone**: third-person declarative, states the contract, does not repeat the name. TSDoc syntax throughout — a malformed tag is an error, not a style nit. `[L1: tsdoc/syntax; jsdoc/require-description]` `[L2]`
   - ✗ `Returns the theme.` on `defaultTheme`
   - ✓ `The theme every generated Angular app starts from; override a token, never the object.`
3. **Tags, in this order:** `@param name - description` (every parameter, TSDoc hyphen form) → `@returns` (every non-void) → `@throws` (every error class a caller would reasonably catch) → `@since` → `@see` → `@deprecated`. Every tag has a description; **no `{type}` in any tag** — TypeScript has it. `[L1: jsdoc/require-param, require-returns, require-*-description, no-types, check-param-names, tsdoc/syntax]`
4. **Release tag on every exported symbol of a package that publishes a library**: `@public` (covered by SemVer), `@beta` (Angular's "developer preview": may change in minor releases), `@alpha` (experimental: may vanish), `@internal` (exported for the package's own tests or sibling packages; not API). One per declaration; a member inherits its container's. `[L1: api-extractor ae-missing-release-tag = error]`
5. **`@author` and `@version` are banned.** Git is the author record. `@since` is written `major.minor` (`@since 0.6`, never `0.6.0`). `[L1: jsdoc/check-tag-names via `tagNamePreference` — error]`
6. **Markdown, not HTML.** Backticks for identifiers, keywords, literals and file names; `{@link Symbol}` for cross-references, `{@link Symbol | text}` when the symbol name is not the right anchor. `<p>`, `<b>`, `<pre>`, `{@code}` and `{@literal}` are Javadoc and do not render. Braces inside prose are escaped (`\{`, `\}`). `[L1: `{@code}` and `{type}` — error (check-tag-names, no-types); HTML tags — warning (no-restricted-syntax); braces — tsdoc/syntax]`
7. **The published surface is a committed golden.** A library package (`ui-kit`) commits `api/<pkg>.api.md` produced by api-extractor; an MCP server (`ai-bridge`) commits `api/tools.api.json` produced by `scripts/mcp-tool-surface.mjs` (every tool's name, description and input schema, canonical order); a generator (`codegen-ts`) commits the generated sample tree its `verify:generated` gate already builds. CI fails on drift; the author accepts a change with `--local` / `--accept`, commits the golden, and classifies it in the PR. This is the TS analogue of ADR-065's japicmp gate. `[L1: tsdoc-gate.yml api-report]`
8. **Removing a tool, an export, or a `required` input is a MAJOR change; adding one is MINOR.** A golden diff with a `-` line and a PR whose *Compatibility impact* says `none` is a [HARD BLOCK]. `[L1: mcp-tool-surface.mjs labels the diff; L2 compares with the PR body]`
9. **Failure modes name the error.** A function that throws documents each error class in `@throws`, and for errors that carry an Exeris code (`EX-*`, a diagnostic id, an LSP error code) names the code. `[L2]`
10. **Category B (generated) files carry the standard generated header and no hand-written doc comments.** The header is one shape for every emitter, produced by one helper that reads the version from `package.json`:
    ```ts
    /**
     * @generated by @exeris/codegen-ts <version> — DO NOT EDIT.
     * Source: <domain>.java (@ExerisDomain <name>) · Regenerate: mvn exeris:generate
     */
    ```
    Generated trees are marked `linguist-generated=true` in `.gitattributes` so PR diffs collapse them, and a PR that edits one without a generator run is a [CATEGORY-B] finding. `[L2: docs-guardrails-review.md Step 4-TS item 20f]` — the `generated` label exists in the organisation taxonomy but nothing applies it: there is no path-based labeler in `exeris-systems/.github`, and no emitter test asserts the header, because no shared helper produces it yet. Both are what 21d is for; until they exist this rule is reviewed, not gated.
11. **Angular applications and internal tooling: rules 2–6 apply to changed files only.** No backfill mandate; `jsdoc/require-jsdoc` is a warning there. Angular-specific: a component's inputs and outputs are documented on the property, in one sentence, boolean ones starting with "Whether"; the class comment says what the component renders and which store it reads, not how. `[L1: diff-aware tsdoc-gate lint]`
12. **Doc comments carry no history.** The same rule and the same sub-rules as `javadoc-conventions.md` rule 12, adapted to TypeScript: state the contract as it is today; `@since` and `@deprecated` are the only temporal tags; the line is the invariant, not its origin; "previously returned null", "used to be", "fixed in 0.8.1", PR/issue numbers, "after the … refactor" and paragraphs on why an earlier design was wrong go to CHANGELOG, release notes or an ADR, which the comment may reference with `@see`. Angular's own rule is the same: *"Docs should describe the framework as it exists now, never relative to a specific point in time."* The gate **warns, it does not fail** — archaeology vs. contract is a reviewer's call — and the regex is the anchored list of ADR-085's 2026-09-05 amendment, shared verbatim between `java/checkstyle-javadoc.xml` and `ts/eslint.tsdoc.mjs` (`previously returned|threw|was|…`, `historically`, `fixed in N`, `used to be|have|read|emit|…`, `after the … refactor|rewrite|migration`, `PR|issue|bug #N`, `workaround for`, `earlier version|design|…`); "no longer", bare "used to" and bare "previously" are left to L2. `[L1 (warning): jsdoc/no-restricted-syntax]` `[L2]`

## Prose rules (Angular coding standards + TSDoc spec, adopted)

- Properties get a one-sentence description of what the value *means*; boolean properties and returns start with "Whether …", not "True if …".
- Methods describe what they do, then every parameter and the return value.
- Present tense, active voice, second person in guidance ("Call `close()` before …"), no "we".
- Do not restate the signature in prose; do not pluralise inline code (`` `Tool` objects``, not `` `Tool`s``).
- `@remarks` holds the paragraphs after the summary when the summary must stay short; `@example` holds a fenced code block, compiled by a test when longer than ~10 lines.
- `@internal` symbols are stripped from typedoc output and from `.api.md`; they are still documented (rule 1 applies to the package's own developers too).

## Example — `ExerisTheme` (`@exeris-systems/ui-kit`), before and after

Before (today's file: Javadoc habits, no release tag, `@author`):

```ts
/**
 * @exeris-systems/ui-kit
 * @author Exeris Team
 * @since 0.1.0
 */
export interface ExerisTheme { colors: { primary: string; … }; radius: { … }; spacing: { … }; }
export const defaultTheme: ExerisTheme = { … };
```

After:

```ts
/**
 * Design tokens a generated Angular application reads at build time.
 *
 * @remarks
 * A theme is data, not a class: consumers spread {@link defaultTheme} and override the
 * tokens they need. Token names are the contract — a removed token is a MAJOR change.
 * @public
 * @since 0.1
 */
export interface ExerisTheme {
  /** Colour tokens by semantic role; each value is a CSS colour string. */
  colors: { primary: string; 'primary-hover': string; … };
  /** Border radii by size step, as CSS lengths. */
  radius: { sm: string; md: string; lg: string; xl: string; full: string };
  /** Spacing scale by size step, as CSS lengths. */
  spacing: { xs: string; sm: string; md: string; lg: string; xl: string };
}

/**
 * The theme every generated application starts from.
 * @public
 * @since 0.1
 */
export const defaultTheme: ExerisTheme = { … };
```

## Example — an MCP tool definition (`@exeris/ai-bridge`)

The tool's `description` string *is* its public documentation (it is what the model reads and what `api/tools.api.json` snapshots), so it follows rules 2 and 12 as strictly as a doc comment; the TS doc comment on the handler documents the implementation contract instead:

```ts
/**

 *          result when the build family is not reachable (see {@link unavailable}).

 * @internal
 */
export async function getDetachState(args: DetachStateArgs): Promise<CallToolResult> { … }
```

## Filter (before you push a gated package)

- Does the first sentence tell a caller what they may assume, not what the symbol is called?
- Is there a release tag, and is it the one the CHANGELOG will have to honour?
- Did the golden change? If so, is the change classified in the PR, and does a `-` line come with a MAJOR bump?
- Is there a `{type}`, a `<p>`, a `{@code}`, an `@author`? Those are Java reflexes — remove them.
- Is there a sentence about the past? Move it to the CHANGELOG or an ADR and leave `@since`/`@deprecated`/`@see` behind.
- For generated output: does every emitted file start with the one header, with the real version?
